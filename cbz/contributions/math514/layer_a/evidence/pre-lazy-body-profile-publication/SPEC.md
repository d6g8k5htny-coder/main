# CBZ Layer A static auditor — bounded specification

Purpose: G0 tests the auditor itself; G1 checks a root-authorized exact tracked-file manifest. This is a focused Python-stdlib command, not a Lean parser, kernel, SAT solver, Python interpreter or general framework. A successful result is `STATIC_PASS`, never CBZ-0 or proof closure.

## Authority and scope

The final federation controller supplies schema v1: exact roots, immutable tree identifiers, complete tracked-file lists, and one hash-bound classification per tracked file. The auditor validates every listed file, exact classification coverage, normalized paths, absence of symlink aliases, UTF-8 where applicable, readability, content SHA256, and all class-specific obligations. It never guesses exclusions or silently skips a file. The authority/completeness of the supplied Git inventory remains G10; this tool deliberately does not run Git. Its report binds manifest bytes, inventory lists and every scanned file. The manifest is supplied outside the audited root in tests; production may bind it as controller evidence outside its own hash cycle.

Classifications: `project_lean`, `math_python`, `engineering_python`, `negative_fixture`, `quarantined_source`, `external_pinned`, `binary_proof`, `documentation`, `data`. Source-looking extensions cannot be relabeled documentation/data. Every source, including quarantined and negative source, is scanned. Retained negative/quarantined source must name its exact expected finding multiset; extra or absent findings fail. Quarantine additionally records an exact nonempty boundary, blocking reason, id and source hash. These records are dispositions, not clean source. Binary proofs require content-bound G2 and G4 evidence references. External files require immutable revision pin metadata; no implicit dependency trust exception exists.

## Mechanical claims

Lean: Root's unchanged canonical Main#698 identifier lexer (`canonical_lean.py`, provenance in `LEXER_PROVENANCE.json`) supplies the hazard stream through a seven-field metadata compatibility adapter; a bounded punctuation/header lexer supplies import/declaration metadata and malformed-input detection. Unsupported token metadata and canonical lexical errors fail closed. Together they handle line comments, nested block comments, ordinary/raw string literals, character literals, escaped identifiers and Unicode identifier boundaries. The canonical engine uses Lean numeric token boundaries, so an adjoining `0axiom` cannot swallow a command keyword. Its conservative brace-hole interpretation scans nested quoted terms inside possible macro interpolation such as `throwError "bad {let x := "safe"; (sorry : Nat)}"`; this may add findings for ordinary brace text and does not certify arbitrary macro semantics. The secondary parser conservatively refuses its unsupported interpolation forms. Outside comments/raw strings, including code in these possible interpolation holes, it detects exact `sorry`, `admit`, `sorryAx`, `admitGoal`, `mkSorry`, axiom/constant declarations, `native_decide`, `native`, `ofReduceBool`, `ofReduceNat`, `ofReduceInt`, `trustCompiler` and `skipKernelTC`, including qualified forms. `addDeclWithoutChecking` (qualified/escaped forms included) is a blocking unchecked-kernel-insertion hazard. Escaped `sorryAx`/`admitGoal`/`mkSorry` constant names remain hazards, while escaped keyword identifiers such as `«sorry»` are not logical placeholders. An exact `native` identifier is always refused, conservatively covering native-decide configuration across whitespace, newlines and nested comments without depending on a follow-text regular expression. Float/Float32 and unsafe/macro/elaborator/FFI syntax are flagged for explicit G2/G4 follow-up because lexical inspection cannot certify its expansion. Imported project macros can inject axioms without these tokens: G2 must enumerate ALL elaborated owned declarations, including private/generated ones, and G4 must kernel recheck them.

Approved foundation declaration profile: **no newly declared owned source axiom is permitted**, even when named `propext`, `Classical.choice` or `Quot.sound`. The approved imported transitive axiom set is exactly `{propext, Classical.choice, Quot.sound}`; only G2's all-declaration kernel environment audit can authenticate that set and those actual declarations. Lexical source naming cannot create an exception to it. Dependencies are immutable pinned inputs, not arbitrary new foundation declarations.

Math Python: an explicit AST allowlist accepts closed-program exact integer/`fractions.Fraction` arithmetic, exact builtins and statically named local functions. No floating/complex literals, `/`, unrestricted powers, arbitrary imports, dynamic calls, reflective attributes, classes, decorators, async, external input, exceptions as proof, or builtin/Fraction rebinding. `**` requires a nonnegative integer literal exponent. Fraction import aliases are supported and protected. This is a conservative syntactic exact-arithmetic profile, not arbitrary interprocedural float-dataflow analysis. Functions are certified only as part of the closed program; external callers are outside the profile. Engineering Python allows floats only with a hash-bound explicit review declaring nonmathematical execution scope; it is parsed and dependency checked, never silently admitted as mathematical certification.

Boundary checks: explicit Lean and Python imports from closed sources resolve through `module_map` to classified pinned files. Closed code cannot import quarantine or negative fixtures, including transitive import chains. Plain Lean module operands include apostrophe, `!` and `?` identifier suffixes; an unsupported operand or trailing token is a gap even after a valid module prefix. Escaped module syntax is outside this bounded import parser and is refused. Python refuses explicit reflective namespace/loader entrypoints in both mathematical and engineering source, including builtins/namespace names and the defined globals/class/frame reflective attributes; a nonmathematical review cannot waive import isolation. Unresolved/dynamic/unsupported import mechanisms are fatal gaps (or exact retained findings in isolated source); no claim of arbitrary runtime dependency completeness is made. The module map must agree with per-file declared module identities and cannot alias names. Retained source requires supported language/module metadata regardless of suffix; an external mapped module also requires a supported source language. Known unsupported source suffixes remain gaps even if labeled Lean/Python. G2/G4 must account for generated modules, macros, FFI and runtime-dependent loading; unknown cases are never green.

A6: every lexical theorem/lemma/example has an entry keyed `name@line` (`example@line` for anonymous examples). Entries are `conditional` with explicit premises/reason, `nonvacuous` with a bound evidence reference, or `vacuous` with a reason. Syntactic candidates (`False` hypothesis, `False →`, opposing `P`/`¬P`, self-strict inequality/disequality, incompatible literal equality) require `vacuous` classification. These are source-shape candidates, not a decision procedure for Lean proposition satisfiability; aliases, typeclass interpretations and arbitrary semantic inconsistency require separate certificates/G2 elaborated statement review. The report lists all detected candidates and all conditional claims.

A7: status JSON is checked only when explicitly bound with `status_evidence`: exact allowed observed state, gate id, command, run id, input hashes, evidence reference and exit code must agree. Observation equality uses canonical JSON serialization so booleans and integers remain distinct. An observation file is evidence structure/content binding, not authentication that the command actually ran. G8/controller execution receipts supply that provenance. Markdown truth and no-weakened-bound historical intent are outside lexical decidability; they require G8 and source-history review respectively.

## Nonclaims and hard limits

No source scanner proves arbitrary mathematics, satisfiability, bound strength, historical test retention, semantic status truth, pin compatibility, kernel trust, command execution or external review authenticity. G2/G3/G4/G5/G7/G8/G10 and relevant manual certificates remain explicit obligations. `STATIC_PASS` covers only the stated mechanical rules under the supplied final tracked inventory. Any missing/unsupported case is a finding/fatal gap, never a skipped green case. Test/mutation scores are finite declared coverage, not a proof of all possible checker behavior.
