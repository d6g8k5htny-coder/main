### Why
- **T1–T3 and T2b.** Orca 46.1's status-bar format has no text field: `labelAndName + roleName + pause + statusBar` (`formatting.py:479-482`).
  - Where Am I falls back to the same format (`formatting.py:1101-1102`).

  - Moved inside the wrapper, the `<p>` is read as an ordinary paragraph. This is the minimal-page result in [539/6403116730](https://github.com/d6g8k5htny-coder/main/issues/539#issuecomment-6403116730), now on the real page.
- **T4.** "grayed" comes from `generator.py:555-567` when SENSITIVE is missing. The replicator's AT-SPI probe shows that neither option is ever sensitive, while the select and its DOM options are enabled.
  - The cause, a select shipped `disabled` and enabled after load, is inferred from the minimal page. No control on this page isolates it.
- **T6 has two mechanisms, both in all three valid runs.**
  1. **The change itself is flushed.** `sig` changes the count to 23, and Orca queues it as a live region (`web/script.py:2392-2396`; `liveregions.py:307-309` presents it about 100 ms later). The `m` press arrives 78–88 ms later and flushes the queue (`input_event.py:855-857` → `web/script.py:526-530` → `liveregions.py:565-566`).
  2. **The rewrites are dropped.** After `sigm` and `sigma` the page rewrites `#equation-count` with identical text. Chromium sends only `children-changed` with a static-text child, which Orca's Chromium script ignores (`scripts/toolkits/Chromium/script.py:159-165, 174-180`). That includes the last rewrite, which no key press follows.
