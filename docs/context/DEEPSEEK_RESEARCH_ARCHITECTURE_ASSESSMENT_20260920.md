# DeepSeek proposal assessment

Assessed on 2026-09-20 UTC against repository commit `d01b69f255243d077a8e9e4bf8706021782a78e6`. This is a design assessment. It installs no new machinery and changes no mathematical status, governing register or frozen artifact.

The strongest next investment is a small certificate-and-replay pilot for the existing RN moment bounds, accompanied by structured diagnostics and different mathematical checks. DeepSeek correctly identifies the project's emphasis on preserving mistakes, checking verifiers and retaining source status distinctions. Its novelty claims, universal guarantees and suggested implementation schedule are not established by the supplied analysis. Several proposed extensions already exist in partial, deliberately limited forms here.

The three starting claims need precision:

- **Preserved error:** `tests/test_bands.py:1089` reproduces the deliberately false decay envelope and verifies that it cannot acquire a certified label through defaults. The comment reports an approximately `2.45e24` discrepancy. The executable numerical check at line 1135 requires a discrepancy greater than `10^20`; it does not freeze that exact factor. The repair was to certification labels and their conjunction, not to the false input's arithmetic. Preserving a failing example and its limitation is valuable without calling it a newly invented primitive.
- **Checking the checker:** `tests/test_claims.py:26` documents the default-argument bug and passes each mutated graph explicitly through `--graph`. This is real, useful evidence that the rejection paths are exercised. It is not evidence that every verifier defect has been excluded.
- **Versioned status:** `claims/graph.json` and the exported registers preserve source statements and conflicting status layers. This records what sources said at observed snapshots, rather than reconstructing a complete history of anyone's beliefs. Some source references remain prose or reading-copy references; not every claim has a complete executable, hash-bound proof chain.

There is clear prior work for the component techniques. Hypothesis explicitly [tests its own testing machinery and retains regression cases](https://github.com/HypothesisWorks/hypothesis/blob/master/guides/testing-hypothesis.rst). Necula's [1998 proof-carrying-code thesis](https://www.cs.cmu.edu/~rwh/students/necula.pdf) describes small proof checkers, binding a proof to the intended predicate, and detecting prover defects through proof replay. [Csmith's 2011 paper](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf) uses differential testing and discusses shared-error limitations. [MADR](https://adr.github.io/madr/) supports rejected and superseded decisions; [event sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) reconstructs historical application states from events. [RFC 9162](https://www.rfc-editor.org/rfc/rfc9162.html) specifies signed Merkle tree heads and inclusion/consistency proofs. These precedents do not settle whether a particular integration is original. They do rule out treating the components as unprecedented merely because the proposal says so. This was a focused prior-art check, not an exhaustive novelty review.

| Extension | Recommendation | Necessary correction |
|---|---|---|
| Proof-carrying claims | Pilot one supported class of exact RN numerical bounds. | Bind the exact statement, law, assumptions, domain, source and verifier version. A script that recomputes an answer is not automatically a sound certificate checker. A concrete object witnesses existence only if the predicate it must satisfy is also checked. A universal claim requires valid coverage or a proved reduction. A pass must not alter canonical status. |
| Counterexample ledger | Extend existing typed witness/margin diagnostics. | Distinguish an actual counterexample, an observed sample margin, a certified uniform margin, a failed sufficient criterion and an unknown result. Most checks cannot honestly produce a globally closest counterexample. |
| Refusal ledger | Add a searchable derived view over material decisions and execution diagnostics. | R17 Work Events remains the disposition record. A second writable authority would create conflicting histories. Record actual decisions/attempts, evidence, reason, scope and reconsideration conditions; do not invent refusals for every action never taken. Deferral, missing authorization, unsupported inputs and mathematical refutation are different outcomes. |
| Adversarial populations | Expand algorithmically different checks at high-risk interfaces. | Already partly present: Stein recurrence, a second-moment trace identity and direct expansion in independent normals. Agreement can increase confidence under stated assumptions; it neither proves correctness nor proves shared assumptions. Disagreement can be an implementation defect with a perfectly precise specification. No majority vote resolves a mathematical dispute. |
| Weighted dependency fabric | Prefer typed logical edges and a derived blocker-path view. | Necessary premises, alternative derivations, applicability conditions and heuristic motivations have different semantics. Numerical weights cannot average away an unmet prerequisite. Keep priority scores separate from validity; preserve frozen and proposed status layers. The current checker already follows transitive prerequisites. |
| Frozen frontier snapshots | Start with source-identified checkpoint manifests only when useful. | Git and existing delivery manifests already bind content. A signature attributes bytes to a key under a trust policy; it does not prove mathematical truth, complete selection or mental belief. A self-supplied timestamp is not independently trusted time. Every-merge signing requires a defined signer, retention and external anchoring policy. |
| Claim fingerprints | Use narrowly defined, versioned identities now; defer general equivalence. | A hash identifies a normalized representation, subject to hash assumptions. It does not establish mathematical equivalence. Same dependencies/type/derivation shape can accompany different constants or conclusions; one theorem can have different proofs. Separate statement, numerical input, derivation, provenance and artifact identities. |

The strongest existing building blocks are concrete:

- `research/slack/registry.py:477` defines `SoundnessWitness`, with exact direction-sensitive violation and margin checks. A loose upper estimate does not become a counterexample simply because its margin looks bad.
- `research/rn/gaussian_families.py:32` returns diagonal-dominance margins, a PSD midpoint witness and an explicit `PSD_MEMBERS_ONLY` or `ALL_BOX_MEMBERS` quantifier. A failed sufficient dominance test is not proof of a non-PSD matrix. The tests include a PSD rank-one singleton with negative dominance margins and a family with a feasible endpoint missed by the midpoint test.
- `engine/operations/rn_applicability.py` and `rn_family_applicability.py` check source identity, dimension, coordinate order, normalization, conditioned law and domain. They do not authenticate that a declared law is the actual RN field law.
- `engine/receipt.py` records failed, skipped and unavailable outcomes, errors and mandatory limitations; `engine/operations/trial.py` records `reason_not_run`. These are useful foundations for a derived refusal view, not a claim that all refusals are already centrally indexed.
- `tools/claims_check.py:288` already prevents restoration of the retracted unconditional Theorem B status. Retraction lineage is more reliable than claiming a structural hash detects every disguised reintroduction. Retraction of one proof or unconditional grade need not refute every conditional form of the conclusion.

The repository has already exposed a fingerprint pitfall that DeepSeek's proposal overlooks. `docs/context/RN_REVIEW_20260920.md:11` found that evaluation cases 105–108 repeated development inputs 0–3, although their case IDs and conditioned-law labels differed. The original full-law hashes therefore missed the numerical overlap. `docs/RN_AFFINE_MOMENTS.md:98` records the correction: compare normalized numerical inputs independently of provenance labels and retain the disclosed overlap. Different identity questions need different hashes.

For a numerical upper claim `f(x) <= C` on `D`, let `S` be a finite tested subset. The observed slack is `m_sample = min_{x in S}(C-f(x))`. It satisfies `m_sample >= inf_{x in D}(C-f(x))`, so a positive sampled margin does not certify the domain. If a validated enclosure proves `sup_D f <= U`, then `m_cert = C-U` is a lower bound on the true minimum slack. A negative `m_cert` is inconclusive when the enclosure is loose. A counterexample requires a valid point in the original domain with a certified violation. Inputs outside the domain are boundary diagnostics, not counterexamples to the stated claim. An SMT relaxation needs its relaxation and objective stated explicitly; “nearly satisfiable” has no universal default meaning.

The recommended first pilot is the existing variance-family control: independent centered Gaussians `X,Y` of variance 1 and `Z` of variance `s in [0,1]`, with `D=XY-Z^2`. The existing exact identities are `E[D^2]=1+3s^2 <= 4` and `E[D^4]=9+18s^2+105s^4 <= 132`. A certificate can carry rational law data, moment derivation, domain and bound, and a separate checker can replay them. A second stage can cover uncertain affine means, covariance families and complete Bernstein subdivisions. These remain generic-law results until actual-field applicability is established.

That pilot should use data in a restricted certificate grammar and a known verifier, rather than executing arbitrary scripts embedded in a witness. Acceptance checks should reject changed coefficients, covariance endpoints, source digests, coordinate orders, domains, quantifiers and inequality directions. They should reject a missing subdivision child or domain gap, malformed rationals and unsupported certificate versions. Timeout or exhausted arithmetic/size budgets must yield no verified result. Record the trust boundary, including parser, exact arithmetic and mathematical rules. A sub-second target is a benchmark for a declared corpus and machine, not a guarantee for all mathematical claims.

After the pilot, consolidate structured diagnostics and refusal records through the existing channels, expand differential checks where they can expose distinct mistakes, and add explicit dependency invalidation. Consider signed frontier attestations only if there is an unmet need to prove historical publication to an external party. Typed dependency analysis and narrowly normalized identities can grow as needed; an automatic weighted scientific-status engine should not be introduced.

The original RN field identification, full spatial coverage, conditioning and weighted Palm composition remain more mathematically consequential than additional global registers. Preserved errors and decision records improve auditability; they do not make a system incapable of omissions, false inputs, shared bugs or misleading records. DeepSeek's day/week/month estimates need measured scope and acceptance criteria before they can serve as a schedule.
