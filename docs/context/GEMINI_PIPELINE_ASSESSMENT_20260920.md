# Pipeline and state proposal assessment

Assessed against research repository commit `d01b69f255243d077a8e9e4bf8706021782a78e6` on 2026-09-20 UTC. This is a design assessment, not deployed code, a canonical status record or authorization for a scientific promotion.

The best fit is a small verification orchestrator over the existing CI checks, with an optional generated context view. The supplied runner, replacement manifests, canonical-state schema, blanket archive move and two-file-only startup policy should not be installed as written. The existing evidence identities and Drive authority should remain intact.

| Proposed component | Finding | Project decision |
|---|---|---|
| Single verification command | Useful way to reduce missed checks and simplify local reproduction. | Reuse the 24 checker invocations and pytest in `.github/workflows/ci.yml`; require a test proving the local command set agrees with CI. Include the two distinct collision-proposal invocations. |
| Python/environment validation | The code accepts Python 3.10+, while this repository specifies Python 3.11. `EXPECTED_ENV_LOCK` is never read, and no dependency versions or signatures are verified. Existing CI also installs an unpinned pytest, so it should not be described as a locked environment. | Record the actual interpreter, platform and pytest version. Define and test an explicit environment policy before making reproducibility or lock claims. |
| Optimized execution | Every suite runs under `-O`, which removes ordinary Python assertions and code conditional on `__debug__`. | Normal execution is mandatory. Optimized-mode negative controls can separately test that security/integrity rejection paths do not depend on assertions; they must not replace the ordinary test run. |
| Input manifest | `manifest.get("files", {})` lets an empty or absent files map pass. JSON duplicate keys are silently accepted. Paths can escape the repository or follow symlinks. No complete expected-input set is required. | Reuse `tools/manifest_integrity_check.py` and `.github/manifest-coverage.json`: 117 manifest identities are currently pinned. Retain declared exclusions, exact source identities and byte counts. A generic empty template adds no assurance. |
| Suite discovery | The four supplied `tests/verify_*.py` and `tests/mutate_*.py` targets do not exist here. Current checkers and negative controls already cover the actual repository. | Use an explicit nonempty command inventory tied to CI. Refuse unknown, missing or omitted required commands; never silently skip them. |
| Reports | The timestamp is fixed, the working directory is inherited, and every run overwrites one report. Manifest/JSON errors can escape before a new report is written, leaving a stale PASS file from an earlier run. | Set the repository working directory; record real UTC start/end, Git commit/tree, dirty state, input identities, command arguments, return codes, durations and log hashes. Emit a unique run receipt and fail on incomplete execution, timeout or invalid input. Preserve prior receipts. |
| Canonical-state schema | It is disconnected from the proposed runner; `STATE_FILE` is unused. It does not require verification receipts or bind a status to source bytes, an operator decision, review or a claim. The field named `booleans` is a string. Nested objects permit undeclared keys in several places. | Keep Drive registers as governing records. A generated context view may summarize them with source IDs, hashes, observation times, extraction rules and unresolved obligations. It must be marked derived and must not become a second claim/status ledger. |
| Archival strategy | Moving all logs, receipts and superseded proposals can break manifest paths, frozen identities and citations. A folder name or read-only filesystem mode does not itself enforce immutable history. | Preserve frozen bytes and paths. Use indexes and explicit supersession links to reduce clutter. Any later relocation needs an audited source-to-destination map and reference checks. |
| Two-file startup | Two summaries cannot supply proof premises, exact input bodies, source freshness, active claims, conflicts, review limitations and applicable repository rules. | Use a compact index as an entry point, then load the exact current governing records and task-specific evidence. Check source identity, current claim/lease and Git head before publication. |

Python's `-O` behavior is documented in the [official command-line reference](https://docs.python.org/3/using/cmdline.html#cmdoption-O). JSON Schema permits unmatched properties unless constrained at the relevant object level; see the [official object reference](https://json-schema.org/understanding-json-schema/reference/object). The supplied removed `$schema` link also needs a real supported dialect URI before it can serve as a usable schema declaration. Date-format validation must be explicitly enabled by the chosen validator.

The repository already separates integrity, scientific status and execution records through `tools/manifest_integrity_check.py`, `tools/claims_check.py`, `tools/receipts_check.py`, `engine/receipt.py` and `engine/bridge/`. The bridge contract remains proposed and not deployed. A convenience runner cannot activate that contract, authenticate an owner decision or grant organizational independence.

A runner implementation should have negative controls for an empty command inventory, missing checker, nonzero exit, timeout, malformed manifest, zero executed tests, stale Git/input identities, optimized execution and attempted report overwrite. State-view validation should reject extra/mistyped fields, unknown references and claims of promotion unsupported by a governing decision. These requirements are a design recommendation; no runner or state replacement was installed in this delivery.

The completed delivery advances the underlying work now: searchable reconciled source identities and archive occurrences, verified active-package payload custody, native Drive navigation, and exact interval-family Gaussian determinant bounds. Its 24 checks, 1,850 passing tests and both successful CI runs validate that implementation within its stated scope. Mathematical review, actual field-law identification and full spatial coverage remain open.
