# RN affine-moment implementation review

Review scope: the new `research/rn/gaussian_moments.py`,
`engine/operations/rn_applicability.py`, `tools/rn_moment_report.py`,
`tests/test_gaussian_moments.py`, and `docs/RN_AFFINE_MOMENTS.md` in the active
research working tree. This is an exposed same-provider technical review,
not organizationally independent mathematical approval.

## Finding: evaluation inputs overlap development inputs

The fixture generator in `tools/rn_moment_report.py` uses the case index only
modulo 7 for the intercept and modulo 5 for the slope and lower covariance
factor. Its complete numerical input therefore has period 35.

Consequently, evaluation cases 105, 106, 107, and 108 have exactly the same
intercept, slope, and covariance as development cases 0, 1, 2, and 3,
respectively. Disjoint integer case IDs do not establish disjoint inputs.
The complete law fingerprint includes the different conditioned-law label,
so comparing those fingerprints would also miss this numerical overlap.

The existing 16-case experiment cannot be described as entirely held out.
This does not invalidate equality of the two algorithms on these cases or
the recorded finite arithmetic costs. It limits the evaluation claim.

Required correction before publication: either describe the retained results
as preselected synthetic evaluation cases with four development duplicates,
or separately freeze a new evaluation set and verify numerical disjointness
before running it. Record the original overlap and the correction chronology.
Do not silently relabel the old plan as if this check had passed originally.
Compare normalized exact numerical inputs independently of labels, case IDs,
and other provenance metadata. Add a regression check for the 35-period alias.

Resolution observed in the working tree: the owner retained the original plan
and all 16 measurements, added a numerical identity independent of labels,
recorded the four duplicate mappings, and changed the result to
`PRESELECTED_SYNTHETIC_WITH_DISCLOSED_DEVELOPMENT_OVERLAP` with
`held_out_claim_valid=false`. The documentation explains the original split
error. No new cases were selected after the finding. The owner reports a
regression for the numerical alias; final committed validation is still due.

## Mathematical checks reviewed

The Stein recurrence reduces total multi-index degree at every recursion.
The determinant expansion uses the RN5 coordinate order `(xx, yy, xy)` and
the polynomial `xx*yy - xy**2`. The separate second-moment trace identity
has the correct noncentral coefficient. The covariance Schur test handles
zero pivots by refusing nonzero residual rows. The Bernstein conversion
uses the correct power-to-Bernstein coefficients and includes both children
at every subdivision. Combining its upper bound with the existing absolute
coefficient cap is valid and cannot weaken the old bound.

The tests compare the recurrence against direct expansion in independent
standard normals, rather than only against itself. Their source, scope,
normalization, and conditioning refusal checks support the stated interface.
These checks do not identify the actual RN field law or complete a spatial
cover, and do not discharge any frozen scientific premise.

This review does not rerun the repository owner's tests. Final full-suite
results, exact committed head, native-file fidelity audit, and Drive custody
closeout must be verified after the owner finishes the change.
