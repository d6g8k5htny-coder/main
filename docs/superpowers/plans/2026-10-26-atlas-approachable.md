# Approachable Atlas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make Atlas easier to enter while keeping reproducibility and limitations inspectable.

**Architecture:** Native disclosures over the existing verified observation and static educational prose; existing persistent status and controller remain. No production dependency.

**Tech Stack:** HTML, existing CSS tokens, JavaScript modules, Python/Playwright; audit tooling is separate.

**Spec:** ../specs/2026-10-26-atlas-approachable-design.md

## Global Constraints

- Exact scientific source/graph/formal/status records unchanged; no new coverage or acceptance.
- Loading/unavailable/refusal, scope and missing/adverse formal evidence stay visible.
- Preserve status roles/child selectors, 2D/list/static, 3D and URL/history behavior.
- Original bytes/paths/revisions archived privately and independently verified before replacement; never delete Drive.
- Separate nonauthor review and nonauthor/nonreviewer integration, current checks/protections.

## Review Focus

- Refused bookmark must not reveal/adopt current snapshot provenance.
- Corrupt source must keep its failure visible and controls disabled.
- Native toggle must keep keyboard focus and full source identities reachable.
- Narrow/large text/forced colors must preserve usable controls and literal identifiers.
- JavaScript absent must retain introductory explanations and original static links.
