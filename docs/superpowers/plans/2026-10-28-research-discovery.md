# Research discovery implementation plan

> For agentic workers: use superpowers:executing-plans for native implementation
> or superpowers:subagent-driven-development for the disjoint Atlas task.

**Goal:** Make acquired mathematical material easy to find and keep verified Atlas
exploration usable when optional status stalls or the displayed3D scope changes.

**Architecture:** Retain native HTML/CSS/modules and one currentSnapshot admission.
Library enhances the existing search DOM and adds a bounded excerpt projection;
Atlas changes only optional-status ordering and camera fitting.

**Tech stack:** Existing browser modules, CSS tokens, Node tests and Playwright.

**Spec:** docs/superpowers/specs/2026-10-28-research-discovery-design.md

## Global constraints

No mathematical payload/classification/edge/status-record/schema/Lean/workflow/
protection edit. Preserve canonical source admission/refusal, historical records,
exact literal source identities, noJS/static fallbacks and peer contrast/Orca
work. Canonical importer keys may change mechanically. No Drive deletion/share
change. Same-family separate engineering review allowed, scienceNONE/org0.

## Review focus

- Source failure must never expose enabled/unqualified discovery or substituted Atlas.
- A late operational response must not steal focus or overwrite another selection.
- Files bookmarks/saves and independent query parameters retain their meanings.
- Same displayed3D node set must preserve orbit/zoom even when selection changes.
- Query text and excerpt content are rendered literally; no new inferred source join.
