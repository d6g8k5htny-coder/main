# Current research site and mathematical atlas

Owner request: maintain every public GitHub Page, incorporate project advances, provide a dedicated interactive mathematical equation/dependency worktree, and update automatically. Standing authorization covers design, implementation, review, integration and deployment. Scientific effect NONE.

## Outcome

Visitors can distinguish current repository observations from preserved historical reading cuts; discover all current public source files; search equations and inspect their exact source; and traverse the actual required and contextual dependency graph. Home, Explore, Research, Library and Mathematics form the five primary destinations; Mathematics links to the existing Dependencies route. All other site pages link to this current view.

## Source and generation

A standard-library static site generator resolves public `main` and `Math-` default-branch commits once per build, reads complete Git trees and required source bytes at those immutable commits, verifies Git blob identities and SHA-256, and publishes `current.json`. The payload includes observation time, both source commits, source file inventory, exact source references, the unmodified downstream GRAPH and its source identity, and equations extracted verbatim from a bounded list of current analytic proof sources. Every equation records path, lines, exact text, hash and commit. Inventory paths in legacy, quarantine, recovery, scratch and private operational material are excluded from public discovery. Existing public source snapshots are not rewritten.

The generator fails before publishing when a tree is truncated, a required source is missing, bytes disagree with the Git blob, or graph edges refer to absent nodes or required edges cycle. It never executes fetched code, infers reviews or promotes claims. Proof index, STATUS and research guide remain pinned source links. Graph classifications are reported verbatim; absent equation, formal receipt or alignment metadata is explicitly not recorded. Equations extracted from another source are an independent source collection; the UI does not invent logical edges between them and the downstream graph.

## Automatic publication

A dedicated GitHub Actions workflow builds on main pushes, every 30 minutes and explicit dispatch. Controls and build have read-only contents access. Deploy has repository-wide `contents:write`, Pages and OIDC permissions. Its standard-library receipt emitter admits only metadata on `refs/heads/codex/site-publication-receipts`, never source-tree writes, force updates or deletion. This script restriction is not a branch-scoped credential. Main must prohibit bot pushes and covering bypass; the receipt branch must prohibit force pushes and deletion. A distinct integrator verifies those platform protections and changes Pages from `main:/docs` to Actions at reviewed integration time. Source author, technical reviewer and integrator remain separate roles.

The workflow runs two actual offline complete Docs builds and requires exact equality. The assembled artifact then passes generated-artifact Chromium admission; its complete fingerprint, exact public manifest/metadata/payload bytes, source commit, run and attempt are handed to deploy through an official pinned artifact action. Browser dependencies have local SHA-256 distribution hashes and install with `--require-hashes --only-binary=:all:`. Deploy checks out the exact tested source commit with `persist-credentials:false`; it executes no artifact or fetched code. PR controls use separate per-PR concurrency groups, while all publication events share one serial group.

Before generation, read the persistent Git receipt independently of Pages and restore all admitted history from fixed-origin manifests and canonical ZIP bundles. An anchored manifest digest rejects an older self-consistent CDN pair. Initial bootstrap requires the receipt branch and both public history pointers to be genuinely absent (404); permission failures, transient errors and malformed state refuse bootstrap. A prepared receipt is persisted before Pages submission. An observed receipt is appended only after bounded exact manifest, metadata and payload readback. With unresolved prepared P, public bytes matching P permit observed-P recovery before the successor. An older observed pair or any differing public state causes HOLD; a job failure after asynchronous submission is not proof that P never published. Unknown outcomes retain the prepared anchor and all its snapshot IDs.

Version 2 mathematical archives retain the recorded graph, acquired equation excerpts, STATUS/research/proof-index byte identities, and graph/node source/review file identities used by the renderer. Their material fingerprint ignores observation time, commit-only movement and unrelated inventory changes; actual changes in any retained source or index bytes create a version. Original archive pins and dates remain immutable. The full current payload, source inventory and convenience pages refresh on every observation. Version 1 archives, their manifests and bundles remain admissible and recoverable. Archive equality is engineering byte equality, not mathematical alignment or scientific acceptance. Closed manifests expose finite coverage and distinguish current observation from historical mathematical material. Disappeared-node routes retain their last historical source-bound reading.

Capacity remains 512 snapshots and 768 MiB of conservatively admitted history bytes, with a visible and CI warning at 75% of either bound. Publication refuses additional versions at capacity and performs no automatic pruning. Historical activity rates give no promise about future capacity. Deliberate archive-first offload would require a separate reviewed procedure; it is not implemented by this change.
