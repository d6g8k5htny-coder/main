## 2: Signed atomic leases

Use a small authenticated lease broker backed by transactional durable storage; evaluate Supabase/Postgres against a central SQLite service before deployment. Operational mutex state is not another Work Events register. Acquire/renew/release/write admission are atomic, issue increasing fencing values, and bind resource/scope/session/claim/source/expected-head/request/grant/expiry in signed canonical capabilities. Signing keys stay solely in the broker, separate from local guidance seals. Clients cannot mint capabilities. Publication checks the current fence and expected head at the actual write boundary, including after pauses/restarts. Legacy active claims are reconciled before activation. A durable idempotent outbox projects receipts to existing Work Events/PR records. The guarantee is participating brokered writes until bypass credentials/legacy writers are actually constrained. Tests cover races, idempotency conflict, expiry, stale writes, tampering, restart and append failure.

## 5: Tier routing

Use a separate deterministic capability/budget broker with LiteLLM provider adapters: routine/navigation goes to admitted local models, ordinary coding/review to admitted economical hosted models, complex mathematical derivations/audits to admitted premium models. Actual provider/model versions are selected from accessible current accounts rather than historical examples. Persistent local worker routes stay local; disabled Kimi is not enabled. Tasks bind disclosure scope, capabilities, allowed providers, request/token/cost limits and explicit escalation reason. Reserve budget before calls, reconcile actual usage, and retain failed/unknown deliveries without automatic paid retry. Hosted secrets never enter model prompts or sandbox environments. Quality benchmarks must support savings per accepted task, including failed and escalated calls.

## 6: Ephemeral execution

Use disposable GitHub-hosted runners for proof/numerical execution and locked-down containers for arbitrary agent code. Source mounts are read-only, outputs separate, network denied by default, user nonroot, capabilities dropped, no new privileges, CPU/RAM/PID/wall/output limits enforced. The first hosted lane bounds output to a 64MiB filesystem, stops/removes the container before collection, refuses symlinks/special files and copies only explicitly allowed regular outputs to a separate trusted publication directory. Host-recorded commit/runtime identities are never container-writable. No host/cloud publishing credentials enter containers. Toolchain preparation is a distinct trusted stage with exact identities. Export full terminal/failure/runtime/source/receipt evidence before disposal. Test filesystem/network/environment/process escape and legitimate work. Container isolation reduces exposure; it does not justify a perfect-protection claim. Existing laptop proof execution is not automatically migrated by adding a workflow. Migration must cover every actual execution entrypoint and record residual paths.
