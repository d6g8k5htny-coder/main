## Review focus

1. Native token counts can disagree with a superficially matching tokenizer/template. Task2 must prove complete uncached prompt-count parity, including special tokens, both entrypoint profiles and non-ASCII text; a character ratio cannot substitute.
2. Similarity can return a stale, excluded, superseded or inaccessible source. Task4 must enforce admission before scoring and again immediately before prompt publication, including a withdrawal racing a selected result.
3. A rebuild can publish mixed generations or a partially persisted vector table. Task4 must preserve the prior complete generation on every staged failure and prove reopen/restart consistency.
4. A relevant sentence can lie after the current12000-character excerpt or in a confusable older version. Tasks1/5 must freeze deep and version-specific answer spans, preserve original byte offsets, and score source identity separately from lexical relevance.
5. Warm cache speed can conceal model loading, embedding/build costs or peer starvation. Tasks5/6 must separate cache states, charge every attempt, measure both roles under load and prohibit installation from warm speed alone.

## Frozen data and interface contracts

`SourceRecord` carries `{source_id, revision_id, source_sha256, extraction_sha256, extractor_version, text_sha256, text_bytes, content_ref, observed_at, policy_epoch, access_state, exclusion_state, supersession_state}`. In the hosted experiment `content_ref` is a manifest-allowlisted relative fixture file, never a URL to fetch. Source and extraction hashes can differ; offsets always address the exact extracted UTF-8 text bytes named by text_sha256. A source update cannot retain an old revision identity with new bytes.

`ChunkRecord` carries source identity plus `{chunk_id, start_byte, end_byte, text_sha256, chunk_sha256, token_count, overlap_tokens, tokenizer_identity, encoder_input_token_count, encoder_tokenizer_identity, splitter_version, embedding_identity}`. Here token_count/overlap_tokens/tokenizer_identity refer to the generator domain; encoder_input_token_count includes the separately verified encoder special-token policy. Both tokenizer identities bind their domain, exact model/manifest/GGUF and tokenizer implementation/settings. Spans are half-open original UTF-8 byte intervals and must round-trip exactly. chunk_id hashes these immutable fields. Citation includes source/revision/text hash and byte span. No silent normalization of whitespace, Unicode, line endings or mathematical notation is admitted.

`GenerationManifest` binds sorted source/chunk inventories, policy epoch, extraction, both tokenizer domains, splitter/encoder/extension identities, embedding dimensions/representation, table count, DB SHA, build statistics and source-admission snapshot. A DB contains one generation. No model-generated provenance fields are admitted. Generation/query caches also bind query bytes, encoder query identity, generator model/template, both tokenizer profiles, role, guidance, context/output/byte limits, selection policy and selected chunk manifest. Encoder or generator identity drift invalidates the relevant complete generation/cache; no old vector is relabelled under a changed encoder.

`RetrievalRequest` is `{query, exact_source_id, exact_ref, role, task_scope, top_k, expected_generation, admission_epoch, freshness_now}`. Query is bounded to2048 UTF-8 bytes and128 independently counted generator tokens; an actual semantic request additionally needs independent encoder token admission under its frozen native context/special-token profile. top_k<=4. Exact ID/ref lookup is first; a valid exact revision request never falls through to another revision by similarity. task_scope is navigation, focused_excerpt or whole_document; similarity alone cannot establish whole-document coverage.

`RetrievalResult` is `{generation, policy_epoch, selection_mode, chunks, citations, coverage, unavailable_reasons, scientific_effect:"NONE",scientific_status_authority:false}`. Modes are `exact`, `literal`, `semantic`, or `no_admitted_source`. Source loss removes support and invalidates cached results; no stale text is returned merely because its vector exists. Unknown freshness/access yields an unresolved result, not an affirmative admission.

`PromptAdmission` binds the exact final serialized request bytes and template rendering, selected evidence/citation manifest, tokenizer count, output reserve and profile identity. It either produces a fully admitted request or a typed refusal. It must not truncate bytes after counting or subtract counts of independently tokenized pieces as though tokenization were additive.
