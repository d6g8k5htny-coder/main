### 1.1 No mirrored artifact is byte-identical to its object

`registers/json/review_queue.json` row `RV-OPS-R17` declares its object as
14,073 bytes, SHA-256 `04987ba4…`. The repository's copy at
`governance/protocols/OP-PROT-019-v1.1_R17.md` is **14,073 bytes, SHA-256
`efcfdd5c…`**. The byte count matches and the digest does not, so a byte-count
check on that file confirms the wrong bytes.

Checked systematically that morning: **0 of 18** mirrored artifacts matched any
of the 325 full digests the registers declare. By afternoon the count was
**3 of 7 restored** (§1.1a below). Two causes:

| file | delta | cause |
|---|---|---|
| `OP-PROT-019-v1.1_R17.md` | +0 B | export normalised the content; byte count coincidentally unchanged |
| `FULL_DOCS_MATH_READ.md` | +239 B | the prepended provenance header, which asserted exactness, was itself the only thing making the file inexact |
| `R17_IMPLEMENTATION_REPORT.md` | +262 B | same; each delta is the header's own length |

(The header's original two-word wording is not reproduced here beside the
file's name, because `tools/provenance_check.py` is literal by design and has
no quotation escape — the same rule the reviews directory applies to promotion
language. This document is held to it like any other.)

The clause violated is in the protocol whose port violated it — `OP-PROT-019`
§2: *"The digest establishes identity, not truth or authorization."*

Fix: `governance/PROVENANCE.json` records declared and actual digests for every
mirrored artifact, none claiming exactness; `tools/provenance_check.py` refuses
to let any file describe a reading copy as verbatim or byte-exact, and names
the byte-count trap instead of passing it quietly. Eleven controls, including a
false-positive control so the corpus's own discussion of byte-exact capsules
does not trip it.

Source: `reviews/records/REV-OPS-R17-001.json`, finding 1.

## 2. Decidable questions, settled by exact arithmetic

Reproduce with `python3 -m research.lpw.headline` and
`python3 -m pytest -q tests/test_lpw_headline.py tests/test_identities.py`.

### 2.1 LPW headline: direction decides admissibility

Exact constant `260 / (3790446482793 · 2⁴⁰ · 10²¹)` =
`6.2385427029355877929430410845…e−44`.

| decimal | position | as upper bound | as lower bound | as equality |
|---|---|---|---|---|
| delivered `6.239e−44` | above exact by `+7.33e−05` rel; correctly rounded to 4 s.f. | **admissible** | not admissible | not admissible |
| proposed `6.238e−44` | below exact by `−8.70e−05` rel | **not admissible** | admissible | not admissible |

The §C repair direction is wrong for an upper bound: a decimal below the exact
value asserts `quantity ≤ 6.238e−44`, which is stronger than the chain
supports. And under an equality headline **nothing rounded is admissible**,
because the reduced denominator carries a prime other than 2 and 5, so the
expansion never terminates. This settles direction-soundness only; it does not
verify the derivation behind the fraction, and qualitative LPW is unchanged.

### 2.2 `E(|ξ|+|η|)⁴ = 12 + 16/π` is false

True value `12 + 32/π = 22.18591635788…`. The claim dropped one of the two
equal cross terms `4E|ξ|³E|η|` and `4E|ξ|E|η|³`, each worth exactly `16/π`.
Exact in the basis `{1, 1/π}`. The sibling audit found one further identity of
that shape in the repository — the Rayleigh fourth moment `Eρ⁴ = 8` — and
confirmed it exact; six items of roughly the right shape could not be settled
and are recorded with reasons. Complete over the repository, incomplete over
the Drive. Refuting the identity flags its consumers; it does not by itself
invalidate any derivation that cited it.

### 2.3 The A1 display-vs-enclosure gap, made numerical

From the three published `I_hi/r³` rung certifications quoted in
`CHART_SIDE_JETMOD_PLAN.md`:

- At the **same** `r = 0.05`, frozen v1 `731.4311` and live v3 `647.8048`
  differ by **12.91%**.
- Under the natural reading of the displayed κ = 1/8 modulus,
  `|Δ(I_hi/r³)| ≤ C·δ^κ`, the two adjacent bands force `C ≥ 23.17` and
  `C ≥ 5.18` — a **4.47×** discrepancy.

Stated with its assumption: this is the natural reading of the displayed fit
applied to `I_hi/r³`, not a quotation of a source's own modulus statement. It
refutes nothing and discharges nothing. It shows, in numbers, why three point
certifications cannot substitute for a band enclosure — which is exactly the
distinction the sources draw and `OBL-H5-JETMOD` names.

## 3. What the certified interval library's audit found

`research/interval/` is the foundation the program lacks: every blocking
obligation demands certified interval bounds, and every computational carrier
in the corpus runs on `mpmath` floats. Four adversarial lenses attacked the
library after it was built. Reproduce with
`python3 -m pytest -q tests/test_interval.py`.

| defect | consequence | fix |
|---|---|---|
| exact-rational `exp` endpoints grow as `1.4427·\|t\|` bits; quadratic through `erf`/`Phi` | `Phi(Interval(-10**5), 1)` was OOM-killed — an unconditional failure on the Gaussian tail, which is what tail bounds need | cap the exponent at `2²¹` bits; past it, underflow degrades to the honest `[0, 2^-limit]` and overflow raises |
| argument sizing used `len(str(n))` | CPython 3.11 refuses `int→str` above 4,300 digits, so `sin`/`cos` of a large argument raised `ValueError` before any arithmetic | bound the digit count from the bit length; an upper bound is the safe direction |
| three containment-breaking mutants survived the whole suite | in `__abs__`, the sign of the `sin` extremum at negative odd multiples of `π/2`, and monotone endpoint selection on wide inputs | one test per mutant, each confirmed to fail against a deliberately broken copy |
| `erf` tail branch clamped `hi` to exactly 1 | valid but crude; a test then pinned the clamp rather than the property | tightened to a real bracket (`1 − erf(8)` in `[1.12230e−29, 1.12250e−29]`, true `1.12243e−29` inside); the test now asserts containment against an independent literal |

The last row is a lesson about tests, not code: a test that records an
implementation fails when the implementation improves.
