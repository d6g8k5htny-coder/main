## 2. Risk-proportionate change paths

**Semantics-preserving maintenance:** correct a stale link, bounded entry range,
format or inaccurate deployment description using an identified old value, current
source, guarded edit, exact readback and rollback record. This does not need six
fresh ceremonies or a new routine human-approval dependency. A maintenance edit may
not change admission criteria, scheduled purpose, permissions, scientific status,
review independence, or the meaning of evidence. Classify a doubtful edit as a
behavior change rather than hiding it as maintenance.

**Material behavior changes:** use PROPOSED -> SHADOW -> PILOT -> REVIEWED ->
ACTIVE_SCOPED -> ACTIVE_GENERAL, with a named finite consumer cohort, representative
acceptance/negative cases, evidence and rollback. Observation does not grant authority;
existing delegated decision authority remains separate and must be stated. General
activation means the explicitly inventoried supported cohort, not every possible
model or inaccessible executor. Expand coverage by a reviewed successor. The new
validator is author-side SHADOW/ISOLATED TESTING, not an enforced admission service.

**Containment:** a demonstrated integrity, privacy, source or collision defect may
justify promptly stopping the specific unsafe use or write. Record the exact defect,
affected target and recovery condition. This neither enables a replacement globally
nor freezes unrelated work. Failed tooling or incomplete adoption evidence alone
cannot convert valid existing mathematical work into a refutation or a global HOLD.

Normal source revalidation and already-authorized research continue throughout.
No new approval stage is inserted into unrelated work by the existence of this audit.

### Git and cross-system publication

The repository's governance/GIT_ADAPTATION.md describes merge as compare-and-swap
on the base head and ordinary merge conflicts as the same guarantee as governance
conflict reconciliation. Those assertions are too strong. Nonoverlapping file edits
can merge cleanly while introducing a contradictory interface or decision. The local
regression suite reproduces that counterexample in a temporary Git repository.

Pin source-policy identity, expected base and exact candidate; revalidate all before
publication; record the actual resulting commit and reconcile semantic consequences.
A preflight read alone is still not atomic. A fast-forward ref update does not
constitute a lock across GitHub and Drive. GitHub's merge `sha` parameter checks the
PR head, not a Drive state or an arbitrary expected base snapshot. Preserve both
contending outputs. No merge/CAS service is installed by this correction.

The research schedule is present on a working branch. The observed default branch
`main` currently has no workflow directory. GitHub schedules run from the default
branch; source presence here is not a deployed scheduled service. Leave the workflow
read-only and do not merge or enable it merely to make an earlier description true.
Its direct failure-propagating lane checks are already present and must be retained.
