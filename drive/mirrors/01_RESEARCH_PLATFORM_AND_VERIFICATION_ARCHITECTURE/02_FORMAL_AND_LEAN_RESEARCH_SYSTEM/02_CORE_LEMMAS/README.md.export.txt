# 02_CORE_LEMMAS


This folder contains atomic, exact-scope terminal objects.


Each lemma folder must contain:


- `statement.md`
- `proof.md`
- `independent_review.json`
- `hostile_tests.py`
- `review_packet.pdf`


Core admission requires:


1. exact object identity and quantifiers;
2. immutable source identity;
3. complete proof or accurately bounded interface;
4. declared dependencies and exclusions;
5. at least one qualifying organizationally distinct exact-hash review when mathematically material;
6. hostile tests or falsifiers appropriate to the object;
7. correction and reopening path;
8. operator approval when canonical promotion is implicated.


Core status never transfers automatically to a parent theorem.




## Operative status layer
Every Core capsule now also contains `CURRENT_STATUS.json`. This file exists because migrated `proof.md` objects may preserve historical pre-closure banners as provenance. Do not edit those proof bodies to modernize their status.


For current 2.0 routing, read in this order:
1. `CURRENT_STATUS.json` — operative exact-scope status, source-identity qualification, migration state, non-effect, and reopen axes;
2. `statement.md` — exact atomic conclusion;
3. `independent_review.json` — review verdict and reopening record;
4. `proof.md` and `review_packet.pdf` — preserved derivation and evidence lineage;
5. `hostile_tests.py` — falsification surface.


## Identity qualification
A semantic terminal theorem and a byte-addressed terminal source are not the same status. If the legacy source lacked a reproducible frozen identity, `CURRENT_STATUS.json` must say so. A newly created snapshot hash requires its own review; historical mathematical approval does not automatically become approval of the new bytes.


## Core Index
The live `Core Index` sheet in FS2_CONTROL_REGISTRY is the navigation and migration surface. It does not replace the capsule files and cannot broaden their conclusions.
