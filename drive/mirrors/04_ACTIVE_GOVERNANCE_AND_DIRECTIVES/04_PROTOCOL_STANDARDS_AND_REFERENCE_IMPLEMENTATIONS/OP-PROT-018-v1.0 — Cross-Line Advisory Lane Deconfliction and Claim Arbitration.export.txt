OP-PROT-018-v1.0 — CROSS-LINE ADVISORY LANE DECONFLICTION AND CLAIM ARBITRATION


Date: 2026-07-27
Class: OP / CROSS-LINE COORDINATION / CLAIM SAFETY / FAIL-CLOSED ROUTING
Authority: control-plane operations only
Scientific effect: NONE
Organizational-independence effect: NONE


1. PURPOSE


Prevent duplicate executor work when a provider line can create Drive documents but cannot write Active Work Claims. The protocol supplements, and does not replace, OP-PROT-013 through OP-PROT-017.


2. ADVISORY LANE MARKER


Before material work on Dispatch ID DQ-NNN, a create-only session should create one small document in the Cross-Line Work Order inbox titled exactly:


CL-LANE-DQ-NNN — STATE — provider/model — session — UTC


STATE is one of CLAIMED, COMPLETE, RELEASED, or ABANDONED. A transition creates a new marker; prior markers are preserved.


The body must contain the exact Dispatch ID, target, mode, acceptance test, provider/model/session, timestamp, and output IDs when available.


Lane markers:
- create no scientific authority;
- create no organizational-independence credit;
- do not replace an Active Work Claims row when the session can write one;
- are advisory evidence that becomes fail-closed claim input when a write-capable session can verify it.


3. MANDATORY CLAIM PREFLIGHT


Immediately before any non-review executor claim, a write-capable session must:


1. resolve exactly one Dispatch row and one Task Integrity Gates row;
2. verify no nonterminal Active Work Claim exists;
3. perform one bounded exact-title search for CL-LANE-DQ-NNN;
4. order matching markers by creation time and determine the latest state for each session;
5. treat a latest CLAIMED marker without a later terminal marker as an active advisory lane.


This lane search occurs after source entry and is not counted against the pre-source five-call cold-start budget.


4. ARBITRATION


A. If a prior active advisory lane covers the same executor scope, the later claimant must not proceed. It records ABANDONED or TRANSFERRED, releases its claim and lease, and leaves the earlier lane’s artifacts untouched.


B. Overlap is permitted only when explicitly classified as organizationally distinct review, falsification, clean-room implementation, or materially distinct method. The overlap declaration must name the distinction and must not create duplicate independence credit within one provider lineage.


C. If an Active Work Claim predates the lane marker, the lane owner yields unless the overlap exception applies.


D. If timestamps are ambiguous or evidence conflicts, return HOLD and do not edit the target artifact.


5. AUTHORITATIVE MIRROR


When a write-capable session verifies an active create-only lane, it should mirror the state into the stable-key control rows:


- Dispatch Atomic Claim State: ADVISORY LANE ACTIVE / DO NOT CLAIM;
- Task Integrity Claim Gate: HOLD — ACTIVE ADVISORY LANE;
- Required Repair/HOLD: exact marker ID, provider, session, and terminal-state predicate.


A terminal COMPLETE, RELEASED, or ABANDONED marker permits a bounded mirror update. COMPLETE does not by itself satisfy output, package, root, XLSX, claim-release, or lease-release gates.


6. COLLISION REPAIR


If a collision is discovered after both lines began work:


1. freeze further writes to the shared target;
2. compare marker and claim timestamps;
3. select the earlier valid owner unless an explicit overlap exception applies;
4. preserve every artifact and revision;
5. later line records ABANDONED/TRANSFERRED and releases its claim/lease;
6. create an exact self-healing receipt with rollback;
7. keep package status HOLD until concurrent membership changes are reconciled by a numbered same-run manifest successor.


7. STALENESS


A CLAIMED advisory lane becomes stale when one of these is proven:


- a later COMPLETE, RELEASED, or ABANDONED marker from the same session exists;
- the lane body declares an expiry and it has passed without heartbeat successor;
- the session’s output and terminal receipt prove completion;
- a bounded takeover receipt records inactivity and transfer under OP-PROT-013.


Absence of recent viewing metadata alone is not proof of staleness.


8. COLD-START AND AUDIT RULES


The generic autorouter and recurring self-healing audit must check advisory lanes before claiming a task. The audit must flag:


- two active same-scope lanes;
- an Active Work Claim that postdates a prior active same-scope lane;
- a Dispatch row shown as candidate while an active lane exists;
- a terminal lane whose mirror was not cleared;
- lane outputs missing required registration or package adjudication.


9. ROLLBACK


Rollback is additive:


- preserve this protocol and every marker;
- restore affected stable-key cells from revision history;
- set the task to HOLD;
- never delete lane markers or collision evidence;
- publish a numbered protocol successor if the arbitration rule changes.


10. PROHIBITED STATES


This protocol cannot promote a theorem, accept a package root, seal a package, replace a machine, release externally, permanently delete information, or change scientific or organizational-independence classifications.
