OP-PROT-016-v1.0 — CROSS-PLATFORM SPREADSHEET FORMULA COMPATIBILITY AND XLSX EXPORT VERIFICATION GATE


Status: ACTIVE CONTROL
Activated: 2026-07-27T00:28:00Z
Scope: GP-REG-032 and every future spreadsheet used as a control, dispatch, manifest, review, evidence, identity, or release surface.
Authority effect: operational integrity only. This protocol creates no scientific result, theorem status, package root, seal, release authority, or organizational-independence credit.


1. MEASURED FAILURE


A live Google Sheet may calculate correctly while its XLSX export contains #NAME? or compatibility wrappers. The reproduced failures were:


- FILTER, REGEXMATCH, REGEXEXTRACT, and COUNTUNIQUE translated to Excel-incompatible forms or __xludf.DUMMYFUNCTION wrappers;
- live Google Sheet readback passed while the exported workbook failed recalculation;
- a statement that “no formula errors exist” was therefore true only for the live Google Sheet and incomplete for the exported artifact.


2. TWO-SURFACE VERIFICATION RULE


A spreadsheet formula change is not complete until both surfaces pass in the same run:


A. LIVE-GOOGLE PASS
- bounded authoritative range returns the expected values;
- task keys, claims, gates, source links, statuses, and counts match the predeclared acceptance test;
- no live #REF!, #VALUE!, #N/A, #DIV/0!, #NAME?, spill, parse, or circular error is present.


B. XLSX-EXPORT PASS
- export the current native spreadsheet to XLSX after the live readback;
- import or inspect the exact exported file;
- scan all computed cells for #REF!, #VALUE!, #N/A, #DIV/0!, and #NAME?;
- scan formula text for __xludf.DUMMYFUNCTION, _xlfn, _xlws, or other unsupported wrappers;
- verify the critical bounded control view and every changed formula cell against the live values.


Either surface failing returns HOLD. A cached or earlier export cannot satisfy this gate.


3. PORTABLE FORMULA PROFILE


Control surfaces intended to survive XLSX export shall use the conservative Google-Sheets/Excel intersection unless an explicit values-only export carrier is published and verified.


Preferred functions:
IF, IFERROR, INDEX, MATCH, LOOKUP, VLOOKUP, SEARCH, MID, LEFT, RIGHT, LEN, MIN, MAX, OR, AND, ISNUMBER, COUNTIF, COUNTA, SUMPRODUCT, SUM, COUNT, and direct cell references.


Prohibited in controlling formula layers unless a same-run exported-workbook test proves compatibility and the protocol is amended:
FILTER, REGEXMATCH, REGEXEXTRACT, COUNTUNIQUE, QUERY, ARRAYFORMULA, IMPORTRANGE, Google-only lambdas, script-defined functions, and any formula exported as DUMMYFUNCTION, _xlfn, or _xlws.


A future formula may not be accepted merely because its live cached value is correct.


4. COLD START CONTROL VIEW REQUIREMENTS


The controlling Cold Start Control View must:


- remain formula-driven and current in Google Sheets;
- use only the portable formula profile;
- enumerate Task Integrity Gate keys through direct row references rather than a spilling FILTER;
- resolve Dispatch and Gate fields through INDEX/MATCH or another portable lookup;
- resolve a live/nonterminal claim without REGEX functions;
- derive Entry Verdict without REGEX functions;
- require a complete https:// entry URL and return MISSING URL fail-closed when none exists;
- populate formulas through the full reserved row range so future Task Integrity Gate rows appear without a structural rewrite;
- preserve identical live values before and after any compatibility rewrite.

6. FUTURE CHANGE GATE


Before releasing any spreadsheet formula or schema change that affects a control surface, the executing model must:


1. acquire the structural-write lease when the edit changes formula topology, sheet structure, protected ranges, or control semantics;
2. record the exact old formula template or revision identity;
3. make the bounded edit;
4. verify the live authoritative cells;
5. export XLSX in the same run;
6. run the full error and unsupported-wrapper scans;
7. compare critical live and exported values;
8. record a receipt and rollback path;
9. release the lease only after readback.


Formula-edit completion is prohibited if the exported workbook was not tested.


7. AUTOMATED HEALTH CHECK


The recurring Drive Self-Healing Audit must verify:


- Cold Start Control View contains no prohibited formula tokens;
- every populated live task row has a nonmissing Exact Entry Source;
- the live key set remains equal to Task Integrity Gates;
- the latest same-run XLSX audit reports zero formula errors and zero unsupported wrappers;
- P0.2 Review Manifest D2 remains portable;
- any newly introduced control formula is either within the portable profile or has an explicit verified exception.


A detected violation returns HOLD and triggers a bounded reversible repair. It must not be hidden by IFERROR fallback values.


8. ROLLBACK


If the portable formulas later produce a live mismatch:


- set spreadsheet export compatibility to HOLD;
- retain the failed exported workbook and mismatch receipt;
- restore the immediately preceding formula templates or spreadsheet revision;
- re-run live verification;
- do not claim XLSX compatibility until a new numbered repair passes both surfaces.


The prior Google-only templates are preserved by spreadsheet revision history and the self-healing receipt. Rollback does not alter scientific data or independence classifications.


9. RELEASE FIREWALL


No spreadsheet carrying a known XLSX formula error may be described as cross-platform verified, release-ready, manifest-ready, or root-ready. The native Google Sheet may remain authoritative for internal use only when the incompatibility is explicitly recorded and all downstream XLSX use is on HOLD.
