1. MEASURED FAILURE BASIS


A response-blind cold-start simulation entered My Drive with no assumed file or folder IDs and reproduced four material failure modes:


F1 — FRONT-DOOR ORDER IS NOT AUTHORITATIVE.
The 00_START_HERE folder returned 01_GENERIC_PROMPT_AUTOROUTER before the 00_AI_DRIVE bootstrap. Provider result position and visible lexical prefixes do not establish authority.


F2 — DIRECT PROMPT SEARCH MISROUTES.
The query “continue Google Drive” ranked the superseded 90_HISTORICAL QUICK JUMP above the live bootstrap and also returned package-specific routers, a sandbox registry marked DO NOT USE LIVE, historical references, and unrelated research files.


F3 — THE THREE-CALL CLAIM WAS PHYSICALLY FALSE.
With the available connector, a true cold start requires separate operations to list root, list the front-door folder, read the bootstrap, read the compact task state, and open the selected source. Semantic stages must not be represented as literal connector-call counts.


F4 — FULL REGISTRY READS CREATE PAYLOAD OVERLOAD.
Reading Dispatch Queue, Active Work Claims, and Task Integrity Gates as broad tables in one operation returns a large payload that is harder to adjudicate, may truncate, and encourages repeated searches or broad rescans.


2. EXACT ENTRY PATH


Normal cold start uses at most five connector calls before opening the selected source:


Call 1. List My Drive root.
Call 2. List the exact 00_START_HERE folder.
Call 3. Open the bootstrap by exact Drive ID 180yfvocozAaFRxf7tY8CDrobnpi17Sv-UkQGBBWCiD8 and verify its first complete line is BEGIN_GLOBAL_CONTROL.
Call 4. Read only Cold Start Control View!A1:N40 in GP-REG-032.
Call 5. Open the machine-derived Exact Entry Source from column N for the selected Dispatch ID. Column K is the complete source bundle and is not itself an entry-selection instruction.


These are five physical calls implementing three semantic stages: authority discovery, bounded task selection, and exact-source entry.


3. RESULT-ORDER AND SEARCH FIREWALL


Never select a Drive object because it is first, newest, lexically smallest, or visually prominent.


The global bootstrap is selected only by exact Drive ID and required prefix.


Direct search of the user’s wording is prohibited during normal cold start. It is available only when root listing or the exact front-door folder fails. A fallback-search result is rejected when its title or context indicates HISTORICAL, SUPERSEDED, REFERENCE, SANDBOX, DO NOT USE, SNAPSHOT, ARCHIVE, or a package-specific READ_FIRST unless the user named that exact package.


One fallback query and one broadened retry are permitted. Repeating broad Drive searches after a valid front door is found is a routing defect.


4. COMPACT TASK-SELECTION SURFACE


Cold Start Control View is the required cold-start task surface. It joins each live Task Integrity Gate to its Dispatch row and current nonterminal claims.


The view exposes:
- exact Dispatch ID;
- rank, priority, mode, and target;
- current eligibility;
- Dispatch claim state;
- nonterminal claim IDs;
- Task Integrity status and Claim Gate;
- complete source bundle;
- machine-derived exact entry source;
- one fail-closed Entry Verdict.


A model must not claim a row marked HOLD, SKIP, missing, claimed, blocked, or runtime/provider incompatible.


CANDIDATE means only that the row survived the structural gate. The model must still filter requested mode, actual provider, available runtime, user constraints, and exact target before claiming.


5. TOOL-CALL CIRCUIT BREAKER


Normal pre-source budget: 5 connector calls.
Recovery allowance: 2 additional calls.
Hard pre-source circuit breaker: 7 calls.


A sixth or seventh call requires a named predicate failure such as missing exact folder, unreadable bootstrap, formula error, missing gate, duplicate key, contradictory claim state, or inaccessible source.


At the eighth proposed pre-source call, stop broad discovery. Record HOLD or a machine-readable CLWO with the exact missing capability or contradiction. Do not continue searching by synonyms, opening status dashboards, scanning whole packages, or reading every register.


Calls used for the user’s requested proof, computation, review, or implementation after exact-source entry are governed by the selected task rather than this entry budget.


6. VIEW HEALTH PREDICATE


Cold Start Control View is healthy only when:
- its Dispatch-ID set equals the live Task Integrity Gates Dispatch-ID set;
- every displayed Dispatch ID resolves exactly once in Dispatch Queue;
- every displayed gate resolves exactly once;
- formula cells contain no #REF!, #N/A, #VALUE!, #NAME?, or spill error;
- nonterminal claim IDs agree with Active Work Claims;
- no HOLD row is displayed as a candidate;
- no live claim is displayed as unclaimed;
- every candidate has a nonmissing source bundle and a nonmissing Exact Entry Source;
- Exact Entry Source equals the first URL in the source bundle, or the first stable Drive ID when no URL is present.


A failed predicate puts the affected row on HOLD. It does not authorize a broad registry scan unless the exact failed join must be repaired.


7. NEW-TASK AND FUTURE-CASE INVARIANTS


Every new task promotion must atomically create its Task Integrity Gate. The Cold Start Control View then includes it automatically through the gate-key formula.


No new task may become claimable when:
- its gate is missing or duplicated;
- its source bundle or machine-derived Exact Entry Source is absent;
- input binding is incomplete;
- provider/runtime eligibility is ambiguous;
- a nonterminal claim exists;
- package impact is unresolved.


Every completed task must satisfy OP-PROT-014 output, Frozen Objects, Identity Drift Watch, package-impact, manifest, root-sweep, claim-release, and structural-lease gates.


8. EXCESSIVE-READ PREVENTION


Cold start must not read:
- the full Dashboard;
- the complete Dispatch Queue;
- the complete Active Work Claims table;
- the complete Task Integrity Gates table;
- Command Center;
- Easy Closure Queue;
- Help Board;
- Open Questions;

- recent documents;
- full Drive search results.


Those surfaces are opened only after an exact selected task, named control-plane failure, or DQ-CONTINUITY predicate requires them.


9. ROLLBACK


If this protocol or the compact view causes a false HOLD, false candidate, or hidden collision:
1. set the affected view row to HOLD by correcting the gate, not by deleting history;
2. preserve the failed formula or trace as regression evidence;
3. revert bootstrap and autorouter through revision history;
4. disable the Cold Start Control View pointer in Config;
5. restore bounded direct reads temporarily;
6. publish an additive repair receipt.


10. REOPENING CONDITIONS


Reopen this protocol on any:
- bootstrap not found by exact front-door path;
- result-order misselection;
- direct-search misrouting;
- pre-source run exceeding seven calls without a named failure;
- view/gate/Dispatch key mismatch;
- false candidate or false HOLD;
- stale claim not reflected in the view;
- new task without a gate;
- package output released without OP-PROT-014 completion gates.
