2. THE BLIND SPOT — AN IDENTITY SWEEP CANNOT DETECT TOKEN-CELL DRIFT


A frozen object has two declarations that must agree: the identity, meaning expected bytes and SHA-256, and the extraction rule, meaning which marker tokens delimit the body. An identity sweep verifies the first. It resolves markers from the object in order to do so.


That is the blind spot. If the register's Frozen Body Rule cell names a token the object does not contain, the sweep still passes, because the sweep never executes the register's cell — it reads the object's own header instead. The wrong cell is then stamped with a fresh PASS, which makes it look verified.


This is not hypothetical. It is measured in Section 3.


The general statement: an object-driven identity sweep is sound for detecting body drift and unsound for detecting rule drift, and the two failure modes require two different checks. OP-PROT-017 rule N4 makes rule drift detectable, but only when the rule is executed from the register rather than from the object.

7. IMPLEMENTATION NOTE I-1 — SHELL PATTERN MATCHING SILENTLY FAILS ON CRLF EXPORTS


Every native Drive export measured by this line is CRLF-terminated with a UTF-8 BOM. A shell check of the obvious form, matching a line anchored at start and end against a marker token, returns zero matches on every such file, because the end-of-line anchor binds before the LF and the CR remains in the way. Two independent verification runs in this session hit this and initially reported zero tokens for documents that plainly contain them.


The failure is silent and returns the same answer, zero, that a genuinely missing token returns. Under OP-PROT-017 rule N4 both produce a hard failure, so the standard is safe; but an implementer debugging that failure will look for a missing marker rather than a line-ending artifact.


This is a third instance of the pattern OP-PROT-017 exists to remove: correct behaviour inferred rather than specified. Rule N3 already requires normalizing terminators before marker resolution, and the reference implementation strips an optional trailing CR when comparing. The note here is that a conforming implementation MUST normalize before matching, and that ad-hoc shell verification does not satisfy the standard and should not be used to check a receipt.
