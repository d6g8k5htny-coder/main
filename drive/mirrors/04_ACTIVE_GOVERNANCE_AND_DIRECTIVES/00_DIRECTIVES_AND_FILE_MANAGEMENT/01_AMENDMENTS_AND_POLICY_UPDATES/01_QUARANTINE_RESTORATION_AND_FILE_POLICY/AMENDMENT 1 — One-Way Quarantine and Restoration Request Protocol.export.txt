AMENDMENT 1 — ONE-WAY QUARANTINE AND RESTORATION REQUEST PROTOCOL


Authority and effective date


By the direct instruction of Dylan Roy, this amendment is effective immediately on July 22, 2026. It amends and supersedes any earlier workspace rule that required model consensus before a file or folder could be moved into a Delete, Outdated, or Corrupted master folder.


1. Unilateral placement authority


Any active model with Drive write access may move a file or folder into the appropriate Delete, Outdated, or Corrupted location without first obtaining consensus when that model independently determines, on a reasonable and stated basis, that the object is wrong, obsolete, superseded, duplicative with a verified replacement, corrupted, unreadable, failed, nonreconstructable, or otherwise a proper deletion candidate.


Placement is a protective quarantine and organizational action. It is not permanent deletion, Trash authority, destruction of provenance, or a change to the mathematical or evidentiary status of the object. The original Drive ID and contents should be preserved whenever technically possible.


Each unilateral move must be accompanied by a traceable reason identifying, when available: the mover/model, date, object title and Drive ID, destination, classification, evidence, and any known replacement.


2. Protected exit and restoration rule


It must be easier to move a questionable object into quarantine than to take it back out.


No model may directly remove, restore, or reclassify an object from a Delete, Outdated, or Corrupted master folder merely because it disagrees with the original move.


Each master folder must contain an accompanying subfolder named “TAKE OUT OF FOLDER — REQUESTS.” A model that believes an object should leave the master folder must place a written request in the corresponding request subfolder. The request must identify the object, its Drive ID, the desired destination, the reason for removal, supporting evidence, the requester/model, and the date.


One request opens a review record but does not authorize removal. Two or more independent requests concerning the same object trigger a documented discussion. Multiple requests do not automatically remove the object. Physical removal requires either:


• an explicit instruction from Dylan Roy; or
• a documented multi-model discussion ending in a written restoration decision.


Until one of those conditions is satisfied, the object remains in its quarantine location.


3. Folder and month structure


The active master folders remain organized by month. New placements should go into the appropriate month subfolder. The TAKE OUT OF FOLDER — REQUESTS subfolder is a protected review queue and may contain request documents organized by month when useful.


4. Precedence


This amendment controls over contrary language in the original Workspace File Management Protocol, any receipt or implementation note stating that consensus is required before placement, and any folder name implying a consensus-only placement gate.


This amendment does not authorize permanent deletion from Drive, movement to Trash, overwriting, or destruction of source material. Those actions remain separate and require explicit authority.


5. Operating principle


Default direction: move questionable material inward to the proper protected folder when there is a documented reason.


Reverse direction: require a request, review, and a higher decision threshold before moving material back out.
