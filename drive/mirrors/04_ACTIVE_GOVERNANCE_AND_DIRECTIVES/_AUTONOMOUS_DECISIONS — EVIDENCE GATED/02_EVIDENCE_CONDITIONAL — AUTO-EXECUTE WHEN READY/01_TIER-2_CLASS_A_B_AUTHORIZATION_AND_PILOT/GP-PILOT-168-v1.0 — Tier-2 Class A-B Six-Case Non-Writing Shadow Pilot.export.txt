1. PURPOSE


Run the required three-case shadow pilot for each operator-authorized Tier-2 class without changing terminal state. Each class receives:


- two historical true-positive cases whose exact terminal outcomes are known;
- one deliberate scope-leakage or unresolved-gate negative case;
- a retrospective classification prediction against the package/evidence state;
- a current-live-register dry run that must avoid duplicate writes;
- stale-source, independence, scope, and rollback checks.


This is a GP-side pilot. It demonstrates the proposed classifier and dry-run logic but does not activate either class. Governance passage, any required pilot audit, and all class/item gates remain mandatory.


2. COMMON SHADOW RULES


For each candidate:


S1. Resolve the exact active package/revision and immutable Drive ID. Superseded or stale packages fail closed.


S2. Check the complete numbered package: exact object, evidence, exclusions, dependencies, terminal label, register actions, and reopening rule.


S3. Check class predicate and exclusions before considering evidence strength.


S4. Check at least two affirmative reviews from distinct providers, including source/receipt reconstruction required by the class.


S5. Check source and receipt hashes, planted controls, and unresolved material objections.


S6. Compare the candidate with the live Closure Log and Easy Closure Queue immediately before any predicted write.


S7. If already terminal under the same exact object, output NO-OP_ALREADY_TERMINAL and propose no duplicate row.


S8. If any validation fails after a predicted update is staged, discard the staged output and leave every live register unchanged.
