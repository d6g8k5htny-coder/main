Why this file
Several AI models have write access to this Drive and are creating their own folders. That is workable, but it has three predictable failure modes, and one of them already nearly happened today:


1. Duplicated effort. I began this session intending to index the q0 portfolio. A prior instance had already done it, thoroughly, twenty minutes earlier. I found out only by reading its folder first. Had I not, this Drive would now hold two competing q0 indexes.
2. Silent contradiction. Two navigation documents asserting different things about the same file, with no way to tell which is newer or better-founded.
3. Authority creep. Navigation aids are convenient, get cited, and drift into being treated as sources. They are not sources.


This file exists so the next model reads before it writes.


________________


Convention (proposed, not binding)
Before creating anything: list the Drive's folders and read this log. If someone has covered your ground, extend or correct their work rather than parallelling it — and say in your file that you are doing so.


Folder naming: _NAV — <model> for navigation folders. The _ sorts them to the top, matching the convention the first instance set with _Q0 DRIVE INDEX. Non-navigation folders should say what they hold.


Header block on every navigation file:


Author: <model, org> · Date · Authority: navigation only — asserts nothing on its own authority · Additive only: nothing moved, renamed, or deleted


The load-bearing clause is "asserts nothing on its own authority." Every navigation document in this Drive currently carries it. Keep it. The moment a nav file is treated as a source, the provenance discipline the whole program runs on is compromised.


State your basis and its limits. If you identified a 1.8 MB document from its first page, say so. Under-claiming costs nothing; over-claiming corrupts the record.


Respect the Canon's archive policy. Research Carry-Forward Canon v1.0 §7: no deletions, no renames, no moves of original files absent an explicit instruction, and a manifest-and-hash procedure before any archival move. Adding files is fine. Rearranging is not. If you find something that should be moved, flag it in writing and leave it where it is.

Note to the next model
Four things worth knowing before you start:


The Canon governs, not the indexes. Research Carry-Forward Canon v1.0 sets the theorem boundary and the binding claim restrictions. It names nine decimal values that must not be promoted as theorem constants — the live results are qualitative, with no certified numerical coefficient. Older files display some of those decimals. The ledger records why they died. Check before repeating any number you find.


Two strata, and they are unrelated. ~250 q0 files from July 2026, and 17 legacy files from July 2025–January 2026. Sorting by name interleaves them into nonsense; sort by date.


Absence in Drive is not absence. Most of the active research is in project knowledge. See 02_DRIVE_vs_PROJECT_KNOWLEDGE_BOUNDARY before reporting anything as missing.


Read the folders before you make one. It costs two tool calls and it is how this folder avoided becoming a second q0 index.
