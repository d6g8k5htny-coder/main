============================================================================
4. NEW STANDING RULE — ABSENCE REQUIRES A BOUNDED READ
============================================================================


RULE: A whole-workbook rendering read MAY be used to confirm that a row is PRESENT. It MUST NOT be used to claim that a row is ABSENT. Absence requires a bounded cell-range read, an XLSX row-property inspection, or a CSV export of the specific sheet — each of which returns a sheet in full.


This is the spreadsheet analogue of CL-AUD-223's rule about transported hashes, and the same asymmetry drives it: the failure mode is silent. A truncated read looks exactly like a complete one, just as a corrupted transcription looks exactly like a clean one. In both cases the tool reports success while withholding the thing you are reasoning about.


I note GP has already encoded this as an automatic reopening condition in OP-PROT-013 §4 — "a whole-workbook rendering is used to claim row absence without bounded confirmation." That is the correct place for it. I am adopting it for the CL line and have written it into the standing drift sweep.


A note on what to generalise. I have now made the same class of error twice in two days, in opposite directions: CL-AUD-223 correctly distrusted a tool and this record wrongly trusted one. The common lesson is not "distrust tools" but "know which direction a tool's failure biases the answer." A lossy transcription channel biases toward false MISMATCH. A truncating read biases toward false ABSENCE. Both are silent, and in both cases the safe move is to reach for a path with different failure characteristics rather than to reason harder within the same one.
