Verdict
Both files are titled EXTERNAL REVIEW PACKAGE — NAVIGATION COMPANION. They are not duplicates. They are two different documents.


Class 3 of CL-REG-007-v1.1 is closed: semantically divergent, confirmed by full read of both. Different structure, different section titles, different coverage. The 5,336-byte copy carries a Recorded roles of the four absent files section and per-file header maps; the 3,566-byte copy reorganizes around per-file titles and adds a housekeeping paragraph the other lacks. Neither is a formatting variant of the other.


This is the only genuinely divergent set in the census. Everything else GP-AUD-004 hashed came back byte-identical or newline-only.

Both copies also state that the four files' contents "did not survive into any recoverable record" and were not reconstructed, per the no-invention rule. The no-invention discipline was correctly applied — the files were not fabricated. But the conclusion drawn from it, that they are absent, is contradicted by their presence in Drive. Per GP-AUD-004 §4, the correct vocabulary distinguishes four conditions: present anywhere in Drive · present in the intended package folder · byte-verified against a specific source attachment · canonical under the authority order. Recommended: whichever copy is retained should be reissued with the absence paragraph corrected. Until then, a specialist reading either one will believe four of seven package files are missing when none are.

Finding 2 — one copy directs a deletion, targeting the exact file GP-AUD-004 ordered preserved
This is the sharper problem.


1WLd0cGT… contains, verbatim in its housekeeping paragraph, an instruction to trash the 15,873-byte copy of 03_NEAR_DIAGONAL_LIFETIME_LAW.md created at 19:36:33Z — naming the 15,874-byte copy as canonical.


That file is 1BXgTbO55zFjQwmgRjrbV_h87z3Jdy9b9. GP-AUD-004 §3.3 ruled specifically on it:


"do not delete or trash the shorter file. Label it as a noncanonical newline variant if needed; preservation remains mandatory."


And GP-AUD-004 §4 states the general rule: "No navigation document may direct deletion. Recommendations such as 'trash it' are outside navigation authority and conflict with the explicit no-deletion instruction."


Three points on this:


1. GP-AUD-004 §6 attributes the trash-a-duplicate instruction to CROSS_MODEL_CONTRIBUTION_REGISTRY_v1.md. It also appears here, in a navigation companion, targeting a specifically-named file ID. Flagging the second location so the ruling can be applied to both.
2. The instruction is technically correct and procedurally out of bounds. The 15,873-byte file genuinely is a newline-short variant — GP-AUD-004 §3.3 confirms it by hash. Being right about which file is canonical does not confer authority to direct its removal. Canon §7 reserves deletion to explicit instruction from the researcher.
3. This is the failure mode CM-001 named, in its most concrete form yet: a navigation document, carrying no theorem authority, issuing an operational command about a source file — and doing so in the reviewer-facing map, where it is most likely to be acted on without checking.


Recommended: the trash instruction should be struck from whichever copy is retained, and replaced with the neutral label GP-AUD-004 §3.3 prescribes.

Finding 3 — both copies claim supersession over the Drive Index, and they disagree on scope
1mWIvwLf… claims it supersedes the _Q0 DRIVE INDEX section titled "Not in this folder" for the items now uploaded. 1WLd0cGT… claims it supersedes the "Not in this folder" paragraph, noting the Index predates the uploads and cannot be edited in place.


Both claims are reasonable in isolation. With two divergent copies asserting supersession over the same target, the effective state is undefined — a reader cannot tell which supersession is in force, and the two copies disagree about which files the superseding statement covers.


GP-AUD-004 §5.5 requires that a new version identify the exact predecessor it incorporates. The same principle applies to cross-document supersession: a supersession claim should name the file ID of the superseded document and the file ID of the superseding one. Neither copy does.

What I did not do
* Did not delete, trash, move, rename, or modify either copy, or the file the trash instruction targets. Canon §7.
* Did not determine which copy is intended as authoritative. Both are plausible; the 3,566-byte copy is later, but CM-001 established that creation time is not evidence of authority. This is the researcher's call, or the authoring model's.
* Did not hash the two. Not needed — a full read establishes semantic divergence directly, which is a stronger result than a hash mismatch.
* Did not reproduce any numerical constant from either document. Both display decimals from the manuscripts. 1WLd0cGT… states that no numerical constant is claimed anywhere in the package and that every finite decimal in the historical record is killed or rung-tagged with ledger line references. Canon §3 governs; nothing is promoted here.
