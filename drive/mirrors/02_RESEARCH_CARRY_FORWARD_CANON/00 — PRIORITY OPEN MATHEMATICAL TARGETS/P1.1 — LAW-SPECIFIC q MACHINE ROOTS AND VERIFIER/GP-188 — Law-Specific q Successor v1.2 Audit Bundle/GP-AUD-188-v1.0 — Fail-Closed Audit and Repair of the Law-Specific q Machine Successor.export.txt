============================================================
1. PREDECESSOR DEFECTS IN DETAIL
============================================================


FINDING QM-01 — Schema/verifier version mismatch


GP-REG-051 declares:


schema = q0-law-specific/1.1.


GP-DATA-022 hardcodes:


if machine.get("schema") != "q0-law-specific/1.0": errors.append("SCHEMA").


Therefore GP-DATA-022 cannot be the validating verifier for the repaired v1.1 snapshot without modification. A local execution against GP-REG-021 does not validate GP-REG-051.


CONSEQUENCE


The phrase `VALIDATED LOCALLY` on GP-REG-051 overstates the exact version-specific evidence unless a separate v1.1 verifier exists and is identified.


MINIMAL REPAIR


Version the verifier and require exact schema equality.


FINDING QM-02 — Nonterminal status vocabulary escapes the blocker closure


GP-DATA-022 uses:


OPEN = {"OPEN", "KILLED", "SUPERSEDED", "RETIRED", "BLOCKED"}.


Its recursive closure adds a claim as a blocker only when its status is in that set. This is unsafe. A claim labeled:


PROVED-IN-ARCHIVE-CLAIMED


or


PROVEN-HERE-PENDING-EXTERNAL


is not independently terminal, but the verifier treats it as nonblocking.


The machine must not infer terminality from every status not explicitly listed as open. Terminality requires an allowlist, not an incomplete denylist.


STRONG REPAIR


Only these statuses are unconditionally terminal:


- INDEPENDENTLY-TERMINAL;
- OPERATOR-TERMINAL.


Every other status is a blocker.


FINDING QM-03 — Claim grade is recorded but unenforced


GP-DATA-022 requires the field `claim_grade` but does not use it in promotion logic. A node may have:


claim_grade = PROVEN-HERE-PENDING-EXTERNAL


and still disappear from the blocker set if its `status` spelling is not in the short OPEN set.


The repaired verifier does not infer proof from claim_grade. Promotion depends on the exact terminal status allowlist, while claim_grade remains descriptive evidence metadata.


FINDING QM-04 — Theorem B dependency graph is incomplete


GP-REG-051 represents:


J_TYPED_CONTACT_LIMIT;
ADJ_POSITIVITY_UNIFORM;
THEOREM_B_ADJ_CONTACT_FACTOR;
Q_ADJ_CONFIGURED_RATE.


This is not enough to establish the persistence lifetime theorem. It leaves unrepresented:


- the exact fold Jacobian;
- the marked candidate-process multiplicity theorem;
- compact-mark versus fixed-mark scope;
- uniform selection over B x K;
- dominated convergence on compact K;
- small-kappa integrability;
- large-kappa integrability;
- off-fold remainder control;
- the full persistence first-moment object.


The schema requirement in the P1.1 READ_FIRST already says J_r, a_r, I_r, and q_adj must remain distinct. GP-AUD-187 shows that even those four objects are not the complete full-Theorem-B graph.


FINDING QM-05 — Historical migration can silently narrow the claim


The historical root THEOREM_B_FULL_KAPPA_C104 denotes a full-lifetime, full-kappa assertion. Mapping it to only a contact factor plus q rate silently drops several theorem obligations.


A migration map must not be treated as a theorem proof. It must either:


- map the historical root to one successor claim whose dependency closure contains every obligation; or
- explicitly mark the migration as a scope narrowing and preserve the historical claim as unresolved.


The repaired migration maps the historical root only to:


THEOREM_B_FULL_KAPPA_CANDIDATE,


whose dependency closure contains the complete open graph.


FINDING QM-06 — Dependency-object smuggling remains possible


GP-DATA-022 permits a dependency ID to name either a claim or an object:


if dep not in claims and dep not in objects: error.


This allows a claim to cite the existence of an object card as though it were a proved claim. An object definition is not evidence that a theorem about that object holds.


The repaired verifier rejects every dependency ID that names an object rather than a claim.


FINDING QM-07 — Alternate dependency routes are not evaluated correctly


GP-REG-051 adds dependency_routes to represent a direct typed route and a redundant route through adjacency. GP-DATA-022 ignores dependency_routes in recursive closure and retains an older hardcoded requirement that Q_TYPED_MS_RATE depend directly on ADJACENCY_TO_ONE_CUBIC.


This contradicts the repaired snapshot’s declared design.


The repaired verifier evaluates each alternate route and uses the least-blocked valid route, while still requiring all non-route base dependencies.
