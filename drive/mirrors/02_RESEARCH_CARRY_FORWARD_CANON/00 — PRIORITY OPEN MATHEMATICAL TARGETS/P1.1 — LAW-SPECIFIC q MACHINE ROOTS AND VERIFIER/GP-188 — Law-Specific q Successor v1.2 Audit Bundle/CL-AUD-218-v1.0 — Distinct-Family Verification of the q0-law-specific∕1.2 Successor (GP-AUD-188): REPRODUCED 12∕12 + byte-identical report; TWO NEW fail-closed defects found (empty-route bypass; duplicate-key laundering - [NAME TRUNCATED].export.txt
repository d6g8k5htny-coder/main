FINDING QM-CL-01 — EMPTY ALTERNATE ROUTE BYPASSES ROUTE OBLIGATIONS (severity: MODERATE; latent).
The route logic selects the least-blocked route (min by blocker count). Appending
{"route_id":"AAA_EMPTY","dependencies":[]} to any route-bearing claim yields a zero-blocker route that
WINS, silently discharging every genuine route obligation. Demonstrated on Q_TYPED_MS_RATE: its declared
route obligations (DEFECT_DICHOTOMY, TYPED_REGIONAL_DEFECT_CUBIC via DIRECT_TYPED_REGIONAL;
Q_ADJ_CONFIGURED_RATE, ADJACENCY_TO_ONE_CUBIC via REDUNDANT_VIA_ADJACENCY) all vanished from the blocker
set and the verifier still returned valid=true.
Why it does not currently promote anything: Q_TYPED_MS_RATE independently carries status PROVED-MODULO
(a blocker) and base dep MORSE_SMALE_R0 (OPEN), so the root stays non-promotable regardless. But the
defect defeats the fail-closed DISCIPLINE that GP-AUD-188 §9 lists as a falsification condition ("an
alternate route is ignored or all alternatives are incorrectly required"), and it WOULD enable promotion
for a future machine whose base/self blockers are cleared. An empty requirement set must never be the
cheapest way to satisfy a route.
VALIDATED FIX (one line, regression-clean): reject empty route dependency lists —
    if not route.get("dependencies"): errors.append(f"{cid}:ROUTE_EMPTY_DEPENDENCIES")
Confirmed locally: the empty-route mutation is now rejected, and the unmodified base machine still
verifies valid=true (no regression).


FINDING QM-CL-02 — DUPLICATE-KEY LAUNDERING AT THE BYTE LEVEL (severity: MODERATE; byte-discipline gap).
json.loads resolves duplicate object keys last-wins. A crafted machine whose bytes contain a second
"MORSE_SMALE_R0" claim with status INDEPENDENTLY-TERMINAL parses to the terminal copy; the verifier —
which sees only the parsed dict — then drops MORSE_SMALE_R0 from the blocker set and returns valid=true.
The clean 12/12 report and matching hash give no signal that the stored bytes were tampered. This is the
machine-schema analogue of the manifest byte-canonicalization gap resolved for TRC (BOM/duplicate/
reserialization); GP-AUD-188 §9 already lists "the verifier report depends on unrecorded local state" as
a falsification condition, and duplicate-key ambiguity is exactly that at the input boundary.
VALIDATED FIX (load with a duplicate-key detector):
    def _no_dup_pairs(pairs):
        seen = {}
        for k, v in pairs:
            if k in seen: raise ValueError(f"DUPLICATE_JSON_KEY:{k}")
            seen[k] = v
        return seen
    json.loads(text, object_pairs_hook=_no_dup_pairs)
Confirmed locally: the crafted duplicate-key bytes now raise DUPLICATE_JSON_KEY:MORSE_SMALE_R0 at load,
before verification.
