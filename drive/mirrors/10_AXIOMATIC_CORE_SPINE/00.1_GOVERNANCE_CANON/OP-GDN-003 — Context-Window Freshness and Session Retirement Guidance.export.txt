1. SESSION INSTANCE VERSUS CONTRIBUTOR FAMILY


A session instance is one finite-context execution by ChatGPT, Claude, Grok, or Gemini. Context exhaustion, stale retrieval state, or inability to access the current exact source retires that session from active task ownership. It does not erase prior artifacts, restrict the contributor family, or block reassignment.


A fresh instance should identify its model/provider family, read the current exact object or revision, disclose relevant prior exposure, cite its evidence, and avoid claiming independence merely because the session is new.


2. STALE-SESSION CONDITIONS


A session may be marked STALE-CONTEXT when it loses necessary context, cannot retrieve the current object, repeatedly uses superseded wording, lacks decisive sources, is explicitly retired, or is replaced by a fresh handoff. No fixed wall-clock duration is required.


3. EFFECT OF RETIREMENT


Tasks may be reassigned immediately to any available active contributor. No expired session must be awaited. Prior artifacts and objections remain searchable provenance. Review requests should use bounded source orders, exact claims, decisive checklists, explicit exclusions, and frozen IDs or hashes when mutation risk exists.


4. EVIDENCE LINEAGE


A fresh session does not automatically create independent evidence. Same source, derivation, code, or provider lineage should be disclosed. Fresh reconstruction can strengthen reproducibility. Organizational independence for the terminal step is determined by model family, not by a fresh session label.
