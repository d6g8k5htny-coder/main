# Development limitations and corrections

1. This author was exposed to the earlier proof architecture; this is not a blind or independent provider-family review.
2. A draft negative-test handler raised an exception even after a mutant survived. Code inspection identified that this would wrongly label a survivor as a detected error. It was corrected BEFORE the final suite. The final driver explicitly runs an intentional survivor twice and checks exit0/UNDETECTED. No faulty draft run is counted as a rejection.
3. Actual partition construction was added after an initial baseline run; the final source and replay use the larger final check count. Older development result files are not controlling. No result count is a confidence estimate.
4. Mutable working paths and generated bytecode are excluded from the frozen archive. Reproduction results are written to a separate output directory.
5. Exact arithmetic handles finite test instances and constant guards; the proof of arbitrary arity/depth is written, not mechanically formalized.
6. Historical defect introduction times, propagation depth, complete billing and agent-hours are unknown and remain null. The observed execution window is not a replacement for those quantities.
7. No external manuscript submission, contact, permission change or q0 scientific-state change occurred.
